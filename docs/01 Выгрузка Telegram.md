# 01 Выгрузка Telegram

## Зачем
Организаторы отвечают в чатах: в общем Q&A, в чате трека, в анонсах, иногда в чате соседнего трека. Через день ответы тонут, а ИИ-агент вообще не видит Telegram. Поэтому выгружаем нужные чаты в markdown, и дальше с ними работают и люди, и агенты.

## Почему клиентский API, а не бот
Бот не читает историю чатов, куда его не добавили, а на хакатоне его никто не добавит. Telethon работает от имени обычного аккаунта участника и видит ровно то, что видит этот участник. Сессия заводится один раз (`login.py`). Выгрузку запускает тот, у кого есть сессия. В нашей команде это был один человек, его агент, остальные читали результат в git.

## Какие источники брать
На О!Хакатоне мы брали шесть источников:

| Источник | Зачем |
|---|---|
| Чат нашего трека | главный: здесь эксперт трека отвечает по существу |
| Чат **соседнего** трека | организаторы общие, и ответ на общий вопрос (сколько регионов, раскроют ли критерии) часто давали там |
| Общий Q&A | сроки, правила сдачи, техника |
| Анонсы (General) | дедлайны, ссылки на документы |
| Презентации проектов | что показывают другие команды |
| Личный чат с ботом хакатона | статус регистрации. **Не для git**: в нём ФИО и почта |

Соседний трек оказался важнее, чем мы ожидали. Часть ответов, на которых мы построили решения, была дана именно там.

## Как устроен `fetch.py`
- **Только чтение.** `receive_updates=False`, только `iter_messages`. Прочитанным ничего не отмечается, в чат ничего не уходит.
- **Метка `[ОРГ]`.** Перед выгрузкой скрипт берёт список админов чата и ставит метку на их сообщениях. Потом анализ идёт в первую очередь по этой метке. Если у аккаунта нет прав на список админов, метки не будет, и организаторов придётся узнавать по именам.
- **Ссылка на каждое сообщение.** Формат строки: `### дата · имя [ОРГ] · [#id](https://t.me/c/…) ↩ ответ_на 📎`. Ссылка открывает сообщение у любого участника чата, и любой вывод в Q&A можно проверить в один клик.
- **`m.text`, а не `m.message`.** В `m.text` сохраняется markdown-разметка. Иначе теряются ссылки, спрятанные в слова («по [ссылке](…)»), а в них обычно и лежат правила сдачи.
- **Догрузка.** Последний id каждого источника хранится в `.state.json`, новый запуск дописывает файл с этого места. Его можно гонять каждые пару часов.
- **`--since`.** Форум хакатона часто общий для всех сезонов, и без отсечки по дате приедут вопросы прошлых лет.

## Подводные камни
- **General-топик форума (id 1)** не адресуется через `reply_to`: у его сообщений нет пометки топика. Скрипт идёт по всему чату и отбрасывает сообщения других топиков.
- **Запрос списка топиков** в разных слоях API живёт то в `messages.*`, то в `channels.*`. Скрипт пробует оба.
- **Код входа не приходит.** Telegram иногда не доставляет код сторонним клиентам, поэтому по умолчанию вход идёт по QR. Код остаётся запасным вариантом (`--code`).
- **«wrong session ID» при входе.** Пока идёт вход, сессию не должен открывать никакой другой процесс, иначе Telegram рвёт вход.
- **Сессию могут отозвать.** После хакатона наша сессия умерла (`AuthKeyUnregistered`). `fetch.py` в таком случае прямо говорит, что нужно перелогиниться.
